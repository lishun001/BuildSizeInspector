# ADR-008 由 Worker 下载 APK

2026-11-23 确认新的默认工作流。Unity Editor 导出报告，Jenkins Shell 上传报告及本次最终 APK 摘要，然后提交该文件的 HTTPS 直链。Worker 复用现有任务、租约、Blob 校验及分析管线。只有实测字节通过清单验证才封存，包体摘要、资源差异和候选原因仍由既有规则生成。兼容 ADR-007 的手工补交和全量上传入口。

公网文件下载须由运维设置精确主机白名单。逐跳验证 HTTPS、证书、主机和 DNS 地址，并通过已校验 IP 建连。流式限制按清单大小与 Worker 期限执行。服务器从请求体接收链接，加密保存在任务中，队列只引用任务 ID。签名链接不出现在日志、回执和网页中。终止或完成时清除，失败可通过同一次构建的更新链接重试。

选择由 Worker 下载，API 可以在报告验收后立即返回 202，并复用现有的重投和故障恢复。替代的同步下载会让 Jenkins 等待大文件传输。历史手工流程适用于发布系统暂时无法提供直链的场景。蒲公英公开安装 API 仅适用于 iOS 或 Android，Jenkins 应由已有发布流程提供 Linux 能直接读取的 APK 文件地址。[蒲公英安装 API](https://api.pgyer.com/doc/view/api_install)

2026-11-24 为已有蒲公英发布中台补齐直链获取。实测授权后的 Key 可在普通 Linux 和 Mac 上请求安装入口，并收到 `cos3.pgyer.com` 的真实 APK 跳转。接入 Shell 复用同一任务的发布凭据和 `buildKey`，提取 HTTPS 文件地址后沿用原上报接口。蒲公英 Key 留在 Jenkins，因为服务器解析方案需要扩大凭据配置及发布身份授权，现有接口已能完成后台下载。桌面调用的实测结果尚未成为厂商文档中的支持承诺。

真实 Jenkins 的鉴权响应还返回了 `pgyer-apps-cfw.appmeme.com`。上报脚本精确认可这一文件主机。运维确认后也需将它加入 Worker 的精确下载白名单，Worker 对每一跳执行 HTTPS、DNS 地址和文件摘要校验。
