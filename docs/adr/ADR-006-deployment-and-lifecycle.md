# ADR-006：本地完整部署、保守保留与恢复证明

日期：2026-11-18，Asia/Shanghai。状态：本地可验证部分已实施，外部验收见实施状态。

## 决策

新增 deploy/compose.yaml，不覆盖根开发 Compose。多阶段前端构建及冻结 uv 依赖；所有基础镜像核验后固定 digest。Python 容器使用 3.12.12，通过显式解释器覆盖本机开发的 3.12.0 请求，不下载额外解释器或更改本机环境。应用 UID 非 root、只读根文件系统、独立持久卷、资源上限、显式迁移和健康依赖。

web 是生产静态包与同源代理，禁用大文件缓冲并设置 2 GiB/超时上限、CSP/nosniff/禁止嵌框。API/数据库/Redis 不映射主机端口。入口覆盖外部转发头，内部 API 才信任代理，已验证变换伪造 X-Forwarded-For 不能绕过登录限流。多级外部 TLS 代理仍需拓扑验收。

2026-11-18 用户已明确确认：“所有 current 修订同时保护原始文件与派生索引，允许长期保留”。该规则适用于所有历史构建的 current，不仅是项目最新版；保留天数只是最早可清理期限，不会覆盖 current 保护。固定基线、pin、活跃任务/上传也保护原始文件；请求中修订和所有比较引用继续保护派生索引。界面与运维说明明确软期限，自动删除保持关闭。现有实现与该决策一致，无需修改运行逻辑。

新增迁移 0006_lifecycle：Build pin、引用 expired_at、Blob gc_marked_at/deleted_at。清单和内容不可改写，过期是独立操作状态。过期引用不能因其他构建仍保有同 Blob 而下载；新上传同内容可重新验证存储，但不恢复旧过期引用。无引用 Blob 经过标记和 24 小时宽限才删除，执行时持项目锁重新核对计划，并绑定存储根/卷身份，避免旧计划误用于另一位置。临时文件独立检查全局上传租约、mtime/inode 和规范文件名；未知/未登记正式文件保留，不执行递归目录删除。

current/比较引用会使指标长期保留；只清理无引用旧修订的明细，留下 EXPIRED 状态与身份墓碑，不能默认为零条目。清理有边界预算、dry-run、计划 SHA、重验证和审计。存储删除走适配器；本地路径只接受服务端规范键，拒绝父目录或文件软链接。

发布与 pin/上传统一 Project→Build 锁顺序，减少反序死锁风险；手动比较在持项目锁后刷新两端指针。新增诊断只返回授权项目的聚合状态和已登记字节，不声称覆盖未知磁盘文件。

备份要求离线停止应用并暂停其他写入，分别保存 pg_dump、已登记 Blob 和校验清单，私有密钥单独保管。恢复先验证来源可信/哈希、连接目标一致和两个目标为空，拒绝覆盖，Blob 逐项有界恢复，无 extractall。随机独立 Compose 项目实际验证了恢复后的登录/token/历史/下载/重分析，不以文件存在替代功能验收。

## 取舍与剩余边界

不停写在线全量备份需要跨数据库与对象的快照协议，首版选择可验证的停写窗口。首版明确保留所有 current 的原始文件和派生索引；今后若要放宽保护、扩大可删除范围，须另行明确决策并更新 ADR 与测试。清理未知孤儿正式文件需要先证明来源，本版保留供人工核对。

性能使用明确合成的 500 MiB/20,000 条目/50,000 Unity 记录，真实 Linux 容器与 PostgreSQL，记录指标和环境。Docker Desktop/共享虚拟磁盘不等同于指定独占 SSD，不能据样本宣布生产 SLA。前端主包体积警告、镜像漏洞扫描、真实 TLS/CI/设备仍保留边界，不以固定 digest 代替安全审核。
